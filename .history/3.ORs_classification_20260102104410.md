### 1. Gene annotation evaluation and homology-based classification (GR and OR)

Following the protocol described in Vizueta et al. (2023), I evaluated and refined the BITACORA annotations for GR and OR gene families using homology-based searches (BLASTP + HMMER) and [get_annotation_classification.pl](https://github.com/molevol-ub/MMB_Chemosensory/blob/main/02_classification_completes/get_annotation_classification.pl).

*1.1. Index gene-family databases for BLAST*
This step is done once and reused across species.
```bash
#GR and OR reference protein databases:
makeblastdb -in DB/GR_PF08395_db.fasta -dbtype prot
makeblastdb -in DB/OR_PF02949_db.fasta -dbtype prot

#“Clean” GR and OR training sets (subset used in HMM profiles, only including 7tm proteins):
```bash
makeblastdb -in ../filter_DB/GR_7tm_hmm.fasta -dbtype prot
makeblastdb -in ../filter_DB/OR_7tm_hmm.fasta -dbtype prot
```     
*1.2. Homology-based searches for GR annotations*
For each species and gene family, I worked inside the family-specific BITACORA output folder (here shown for GR: GR_PF08395/):
```bash
ANNOTATIONFASTA=OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta

# BLAST of GR annotations against GR reference DB
blastp -query $ANNOTATIONFASTA \
       -db DB/GR_PF08395_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_GRblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# BLAST of GR annotations against OR reference DB (to detect mis-annotated ORs)
blastp -query $ANNOTATIONFASTA \
       -db DB/OR_PF02949_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_ORblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# BLAST of OR annotations against the “clean” OR training set
blastp -query $ANNOTATIONFASTA \
       -db ../filter_DB/OR_7tm_hmm.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_ORcleanblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# HMMER search of OR domain against BITACORA OR proteins
hmmsearch -o "${ANNOTATIONFASTA}_hmmer.out" \
          --notextw \
          --tblout "${ANNOTATIONFASTA}_hmmer.tblout" \
          --domtblout "${ANNOTATIONFASTA}_hmmer.domtblout" \
          DB/OR_PF02949_db.hmm \
          $ANNOTATIONFASTA
```

I then configured [OR_get_annotation_classification.pl](scripts/OR_get_annotation_classification.pl) for OR (example shown here for Cx. pipiens; paths adjust per species):

#genome and annotations

Then I run the script_
```bash
perl OR_get_annotation_classification.pl
```
This step classifies GR annotations into complete, partial/pseudogene, fragment, or discarded copies, and removes clear OR-like false positives based on the filtergenefamilyname BLAST.

Among other outputs, the script generates summary tables:
* OR_gene_table.tsv
* OR_summary_table.tsv

**Important note on OR_get_annotation_classification.pl**: The original [get_annotation_classification.pl](https://github.com/molevol-ub/MMB_Chemosensory/blob/main/02_classification_completes/get_annotation_classification.pl) script was developed for gustatory receptors (GRs) and required a minimal correction to be reliably applied to olfactory receptors (ORs). When adapted for OR analyses, the BLAST output files were read into internal variables (%orblast and %grblast) in an inverted manner, causing OR BLAST hits to be interpreted as GR evidence and leading to the systematic misclassification and exclusion of true ORs. This was resolved by correcting the assignment of BLAST outputs in the “Reading blast output” section of the script, ensuring that BLAST results against the OR reference database (*_ORblast.txt) are stored in %orblast, while BLAST results against the GR reference database (*_GRblast.txt) are stored in %grblast. No other aspects of the script were modified: the OR/GR decision logic, length-based classification, fragment handling, and discard rules were left unchanged. After this correction, ORs are correctly identified based on relative BLAST support against OR versus GR databases, while preserving the original curation logic of the pipeline. **This note is importante because the original script had a portion of it that stated that commenting/uncommenting some lines would be enough to make the script work for OR or GR. However, this further inspection revealed that this was not the case, and a deeper correction was necessary to ensure accurate OR classification.**

### 2.Gene Filtering and Curation Criteria
Filtering criteria applied:

1. Homology-based filters
       * Removal of OR contaminants using BLASTP outputs (as implemented in get-annotation-classification.pl).
       * HMMER domain support required (PF08395 7tm chemoreceptor domain).
2. Presence of transmembrane (TM) domains
       * Predicted using TOPCONS.
       * Minimum of 7 TM domains required for complete GRs (8 allowed, see below).
2. Protein/domain length filters
   * ≥296 aa (80% of average full-length GRs domain). In the case of ORs this was already applied in OR_get_annotation_classification.pl
   * Partial GRs: 50–296 aa.
   * Excluded: Proteins <50 aa or pseudogene-like fragments.
   * Length outliers (>450 aa) flagged for manual review.
3. BLAST warnings (“multiple top hits”) reviewed case-by-case in downstream analyses

Thus, only genes with length ≥254 aa, HMMER domain support, and 7-8 TM domains were classified as complete GRs.


#### 2.2 Transmembrane Domain Prediction
TM domains were predicted using [TOPCONS](https://topcons.cbr.su.se/). The zipped file with results was parsed with [run_Parse_TOPCONS.sh](scripts/run_Parse_TOPCONS.sh).

```bash
bash run_Parse_TOPCONS.sh 2>&1 | tee GR_topcons_$(date +%Y%m%d_%H%M).log
```

Then we used the combined results to filter GRs with at least 6-7 TM domains. ORs are proteins with 7-transmembrane domains. To check the best way to filter TOPCONS results, I downloaded from [FlyBase](https://flybase.org/search/#/page/1)) all the prtoeins sequences corresponding to the OR family (PF02949 ) in Drosophila melanogaster (64).  98.2% of them (60) had 6 or 7 TM domains predicted. Given this proteins are well studied, we considered that this is a good reference to set our TM domain filtering criteria. Therefore, we decided to keep only ORs with 6 or 7 TM domains predicted by TOPCONS as complete GRs.

#### 2.3 Final OR curation
We combined the results from *get_annotation_classification.pl* (length and homology-based classification) with the TM domain predictions from TOPCONS to generate a final curated list of OR genes for each species. We used [tables_curado_OR.R](scripts/tables_curado_OR.R) to generate a merged table with all relevant information and applied the filtering criteria by hand using Excel to be able to check each gene individually.
