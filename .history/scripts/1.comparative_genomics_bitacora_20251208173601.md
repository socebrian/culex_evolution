### 3. Prepare input files for Culex species
**1. Culex reference genomes and annotations**

I downloaded reference genomes/annotations from Ensembl for:
* Culex perexiguus GCA_964243045.1
* Culex laticinctus GCA_964187845.1
* Culex theileri GCA_964340515.1
* Culex modestus GCA_964213205.1

I downloaded from NCBI:
* Culex quinquefasciatus GCA_015732765.1
* Culex pipiens pallens GCA_016801865.2

For Culex pipiens pipines, I used reference annotation obtained with Eviann for the reference genome GCA_963924435.1 (see in [Cx pipiens popgen project](https://github.com/socebrian/pipiens_popgen/tree/main)).

There was no reference genome with available annotation for Culex pipiens molestus. 

To prepare the references and annotations for BITACORA, I did the following steps (when needed):
 * transform format of gff from NCBI
 * filter annotations to include only longest isoform per gene 
 * obtain fasta proteome files from genome + gff 
 
 
* *Reformatting of NCBI GFFs*: As stated on BITACORA manual, GFFs from NCBI need to be reformatted. I used :
 ```bash
 #for Cx. quinquefasciatus and Cx. pipiens pallens
 perl Scripts/Tools/reformat_ncbi_gff.pl $ref_ncbi
 ```

* *Filtering to longest isoform per gene*: I used AGAT to keep only the longest isoform per gene in the GFF3 files:
```bash
agat_sp_keep_longest_isoform.pl \
    -gff $ref_gffs \
    -o $output_gff3
```
Done for Cx. pipiens (EviAnn annotation) and genomes downloaded from ENSEMBL (Cx. perexiguus, Cx. laticinctus, Cx. theileri and Cx. modestus). NCBI annotations already had only one isoform per gene.

* *Generating proteomes from genome + gff*: I used BITACORA script *gff2fasta_v3.pl* to generate proteomes from genome + gff files downloaded from NCBI:
```bash
perl Scripts/gff2fasta_v3.pl $ref_fasta$ \
                             $ref_gff3$ \
                             $prefix
```
This was done for Culex pipins pipiens (EviAnn annotation) and references from ENSEMBL (all the references in which we had to filter to longest isoform per gene).


**2. proteina database y hmm profiles**
We are gonna do analyses based on 3 gene families: GR, OR and OBP.
 1. Search in [Pfam](https://www.ebi.ac.uk/interpro/) (hosted in IntterPro) the hmm profiles for these families and download their HMM profiles
 2. Download of the protein database: Under the Taxonomy section, we downloaded the protein database for the group Insecta, in both TSV and FASTA formats (InterPro provides scripts that can be used to automate this download).
3. Processing and filtering of the database
    a. In the TSV file, we calculated the average domain length for proteins with reviewed status.
    b. We set the minimum domain length threshold to 80% of this average.
    c. We filtered out all proteins whose domains had a length below this threshold.
    d. We also discarded proteins that contained more than one domain.
    e. We then filtered the FASTA file accordingly.
4. Generation of the input for the HMM analysis: Using the HMM profile and the filtered protein database, we obtained the final input required for the BITACORA analysis.

Fasta files for protein databases are obtained from Uniprot --> https://www.uniprot.org/

In the case of GRs we have two types of proteins:
* PF06151 Trehalose receptor 
* PF08395 - 7tm Chemosensory receptor
Proteins from both families are added to the protein database, but only the 7tm protein is used in the hmm profile, since they have different structural patterns and it becomes confusing to search for them if you enter both.

We have no further information about code/scripts used in this process, as the final files were provided to us but experienced collaborators. This data can be obtained from them if required for reproducibility.

### 4. Running BITACORA for Culex genomes
Once genomes, GFF3 annotations (reformatted and, when needed, filtered to longest isoform per gene) and proteomes were ready, I ran BITACORA in full mode for all species using custom shell scripts. All runs used the same general command:

```bash
perl runBITACORA_command_line.sh -m full \
     -q $DB -g $GENOME -f $GFF -p $PROT \
     -n $SpeciesID -t $NSLOTS -r T -sp Scripts
```

where:
* DB is the directory containing the gene-family query databases (FASTA + HMM).
* GENOME is the soft-masked genome FASTA.
* GFF is the (possibly reformatted and isoform-filtered) GFF3 annotation.
* PROT is the corresponding proteome FASTA.
* SpeciesID is a short species label used by BITACORA in its outputs.
* NSLOTS is the number of threads requested.
* -sp Scripts points BITACORA to its Scripts directory.


I created a script in which I directly state the input used by *runBITACORA_command_line.sh*. 
Example:
```bash
#!/bin/bash
# run-bitacora-1pipiens.sh
SpeciesID=CxpPip
NSLOTS=15
DB=DB
GENOME=data/culexPipiens.softmasked.fasta
GFF=data/culexPipiens.eviann_annotation_longest_reformat.gff3
PROT=data/culexPPipiens_longest.pep.fasta

date
perl runBITACORA_command_line.sh -m full -q $DB -g $GENOME -f $GFF -p $PROT \
     -n $SpeciesID -t $NSLOTS -r T -sp Scripts
date
```
Run command:
```bash
cd 1.pipiens
bash run-bitacora-1pipiens.sh 2>&1 | tee bitacora_pipiens_$(date +%Y%m%d_%H%M).log
```
