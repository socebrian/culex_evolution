5. Gene annotation evaluation and homology-based classification (GR and OR)

Following the protocol described in Vizueta et al. (2023), I evaluated and refined the BITACORA annotations for GR and OR gene families using homology-based searches (BLASTP + HMMER) and the get_annotation_classification.pl script.

5.1. Index gene-family databases for BLAST

This step is done once and reused across species.

# GR and OR reference protein databases
makeblastdb -in DB/GR_PF08395_db.fasta -dbtype prot
makeblastdb -in DB/OR_PF02949_db.fasta -dbtype prot

# “Clean” GR and OR training sets (subset used in HMM profiles)
makeblastdb -in ../filter_DB/GR_7tm_hmm.fasta -dbtype prot
makeblastdb -in ../filter_DB/OR_7tm_hmm.fasta -dbtype prot

5.2. Homology-based searches for GR annotations

For each species and gene family, I worked inside the family-specific BITACORA output folder (here shown for GR: GR_PF08395/):

ANNOTATIONFASTA=GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta

# BLAST of GR annotations against GR reference DB
blastp -query $ANNOTATIONFASTA \
       -db DB/GR_PF08395_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_GRblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# BLAST of GR annotations against OR reference DB (to detect mis-annotated ORs)
blastp -query $ANNOTATIONFASTA \
       -db DB/OR_PF02949_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_ORblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# BLAST of GR annotations against the “clean” GR training set
blastp -query $ANNOTATIONFASTA \
       -db ../filter_DB/GR_7tm_hmm.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_GRcleanblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# HMMER search of GR domain against BITACORA GR proteins
hmmsearch -o "${ANNOTATIONFASTA}_hmmer.out" \
          --notextw \
          --tblout "${ANNOTATIONFASTA}_hmmer.tblout" \
          --domtblout "${ANNOTATIONFASTA}_hmmer.domtblout" \
          DB/GR_PF08395_db.hmm \
          $ANNOTATIONFASTA


I then configured get_annotation_classification.pl for GR (example shown here for Cx. perexiguus; paths adjust per species):

# Genome and GR gene-family annotation
my $genome      = "data/idCulPerx1.1.softm.genomic.fa";
my $annotgff    = "GR_PF08395/GR_PF08395_genomic_and_annotated_genes.gff3";
my $annotprot   = "GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta";

# GR family name and homology search inputs
my $genefamilyname      = "GR";
my $blastoutput         = "GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta_GRblast.txt";
my $filtergenefamilyname= "OR";
my $filterblastoutput   = "GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta_ORblast.txt";
my $hmmeroutput         = "GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta_hmmer.domtblout";

# Clean GR BLAST (used as high-confidence references)
my $dmelblastoutput     = "GR_PF08395/GR_PF08395_genomic_and_annotated_proteins_trimmed.fasta_GRcleanblast.txt";

# Length thresholds (aa) for GR
my $completelength = "350"; # complete copies (~95% of GR domain)
my $minlength      = "200"; # partial/pseudogenes (50–200 aa labeled as fragments)
my $maxlength      = "535"; # sequences longer than this are flagged as possible chimeras


I wrapped the call to the Perl script in a shell launcher for logging:

bash run_annot_classif.sh 2>&1 | tee GR_annot_classif_$(date +%Y%m%d_%H%M).log


This step classifies GR annotations into complete, partial/pseudogene, fragment, or discarded copies, and removes clear OR-like false positives based on the filtergenefamilyname BLAST.

5.3. Homology-based searches for OR annotations

I repeated the same strategy for ORs using the OR-specific BITACORA output folder (OR_PF02949/). Example:

ANNOTATIONFASTA=OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta

# BLAST of OR annotations against GR and OR reference DBs
blastp -query $ANNOTATIONFASTA \
       -db DB/GR_PF08395_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_GRblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

blastp -query $ANNOTATIONFASTA \
       -db DB/OR_PF02949_db.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_ORblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# BLAST of OR annotations against the “clean” OR training set
blastp -query $ANNOTATIONFASTA \
       -db ../filter_DB/OR_7tm_hmm.fasta \
       -outfmt "6 std qlen slen" \
       -out "${ANNOTATIONFASTA}_ORcleanblast.txt" \
       -num_threads 1 \
       -max_target_seqs 5

# HMMER search of OR domain against BITACORA OR proteins
hmmsearch -o "${ANNOTATIONFASTA}_hmmer.out" \
          --notextw \
          --tblout "${ANNOTATIONFASTA}_hmmer.tblout" \
          --domtblout "${ANNOTATIONFASTA}_hmmer.domtblout" \
          DB/OR_PF02949_db.hmm \
          $ANNOTATIONFASTA


For ORs, I used a slightly different set of length thresholds:

# Example configuration for ORs (Cx. pipiens)
my $genome      = "data/culexPipiens.softmasked.fasta";
my $annotgff    = "OR_PF02949/OR_PF02949_genomic_and_annotated_genes.gff3";
my $annotprot   = "OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta";

my $genefamilyname      = "OR";
my $blastoutput         = "OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta_GRblast.txt";
my $filtergenefamilyname= "GR";
my $filterblastoutput   = "OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta_ORblast.txt";
my $hmmeroutput         = "OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta_hmmer.domtblout";

my $dmelblastoutput     = "OR_PF02949/OR_PF02949_genomic_and_annotated_proteins_trimmed.fasta_GRdmelblast.txt";

# Length thresholds (aa) for OR
my $completelength = "302"; # complete copies (~95% of OR domain)
my $minlength      = "175"; # partial/pseudogenes; 50–175 aa = fragments
my $maxlength      = "477"; # warns on very long/chimeric candidates


Again, I launched the classification with:

bash run_annot_classif.sh 2>&1 | tee OR_annot_classif_$(date +%Y%m%d_%H%M).log


At this stage, GR and OR families had been refined per species, with:

Gene copies classified as complete, partial, or fragment based on alignment length.

Mis-annotated copies (e.g. OR-like sequences in the GR set, or vice versa) flagged and removed according to cross-family BLAST results.

Work on OBPs will follow the same strategy (family-specific BLAST/HMM searches and length thresholds) once final parameters are agreed.
